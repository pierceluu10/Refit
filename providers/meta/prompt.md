Meta's Graph API (Facebook Pages, Instagram Graph, Marketing API) is versioned in the URL path: `https://graph.facebook.com/v25.0/{node}/{edge}`. A new version ships a few times a year and each one stays available for at least two years; the versions page lists release and expiration dates, and the Marketing API keeps its own, usually shorter, expiry table. Unversioned calls use the version set in the app dashboard, and calls to an expired version are served by the oldest version still available, so an expiry date is an `api-version` change whose `affects.versions` names the version going away (e.g. `v20.0`) and its `effectiveDate`.

Each per-version changelog (`/docs/graph-api/changelog/versionNN.0`) has Graph API and Marketing API sections. Most entries say "Applies to vNN.0+" and then a later date when they reach all versions: treat that later date as the `effectiveDate`, because that is when pinned callers break. Report each entry as its own change, with the nodes and edges it names in `affects.operations` (as written, e.g. `GET /{page-id}/insights`, `POST /act_{ad-account-id}/adsets`), and fields, insights metrics, query parameters, permissions, webhook fields or placement values in `affects.fields`. Removed metrics and fields with a named replacement may be `field-renamed`; ones with no replacement are `field-removed`; whole APIs going away are `endpoint-removed` or `product-shutdown`; webhook certificate or payload changes are `webhook-payload`; access tiers and permissions are `auth-change`.

The Meta Business SDKs (`facebook-nodejs-business-sdk` on npm, `facebook_business` on PyPI, `facebook/php-business-sdk`, `facebook-java-business-sdk`, `facebook-ruby-business-sdk` gem) are generated and their major number tracks the Graph API version, so a new SDK major is `sdk-major` with the SDK package in `affects.sdk`. Skip purely additive fields, new features that need no code change, documentation reshuffles, and point releases whose notes only say "Full Changelog".

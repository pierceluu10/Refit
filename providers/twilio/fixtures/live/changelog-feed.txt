Voice Insights now tags HD audio calls

Voice Insights now tags calls as HD Audio when they connect with the AMR-WB or Opus codec.
Use the tag to confirm your endpoints negotiated what you configured, and to correlate HD usage with transcription accuracy, AI agent performance, and customer satisfaction.
Calls that carry HD audio are tagged as Downsampled when the longest portion of the call connects to a component or another endpoint that does not support HD. Twilio converts the audio to narrowband to keep the call connected.
Both tags appear in the Call Summary in Console, in the Voice Insights REST API, and through Event Streams. You can also filter the Call Insights dashboard by either one.
Learn more in our Call Summary documentation .

Segment Conversation Memory Integration now in GA

The Segment Conversation Memory Integration is now in GA. You can now sync long-term customer profile data, like identity and lifetime value, from Segment into the sub-second recall of Conversation Memory, enabling both AI and human agents to instantly access unified context during live interactions. This eliminates cold starts, reduces repetitive questions, and delivers highly personalized, continuous customer experiences across all channels.
The integration continuously syncs long-term customer profile data, such as identity and historical traits, from Segment directly into Conversation Memory. Customers configure this transfer using either "Memory Sync" to rapidly import their entire profile database or "Memory Destination" to target specific user cohorts via Segment Audiences. During setup, Segment profile traits and identifiers are mapped to corresponding semantic trait groups within a Memory Store. Once active, trait updates flow in real time, allowing AI or human agents to instantly query the Memory Store for up-to-date customer context during live interactions.

Voice Insights now shows why carriers block your calls

Voice Insights now tells you why a carrier blocked your call and how to reach that carrier for redress.
The FCC requires carriers that block calls using analytics to return the reason header to the caller. It names the network that blocked the call and tells you how to contact them: a URL, a phone number, or an email address. Until now a blocked call showed you only a 603 response. Now you can see which network blocked it and petition them directly.
The reason header appears alongside Last SIP Response in the Call Summary, in Twilio Console, the Voice Insights REST API, and Event Streams.
If you are seeing a high volume of 603 responses, confirm your traffic is signed with STIR/SHAKEN and registered with Twilio Voice Integrity before you start filing redress requests.
Learn more in our Call Summary documentation .

Account Rate Limits on Content API

What is Changing?

To improve platform stability, endpoint reliability, and system performance, Twilio is introducing standardized rate limits for Content API requests.
Rate limits will be enforced at the account level. Requests exceeding these limits will receive an HTTP 429 Too Many Requests status code.

Rate Limits by Endpoint

Read Operations

Fetch Content (GET /v1/Content/{Sid}): 100 RPS

Fetch Approval (GET /v1/Approval/{Sid}): 100 RPS

List Content (v1 & v2) (GET /v1/Content): 20 RPS

List Content & Approvals (v1 & v2) (GET /v1/ContentAndApprovals): 20 RPS

List Legacy Content (GET /v1/LegacyContent): 20 RPS

Write Operations

Create Content (POST /v1/Content): 100 RPS

Create Content Approval Request (POST /v1/Approval): 100 RPS

Update Content (POST /v1/Content/{Sid}): 20 RPS

Delete Content (DELETE /v1/Content/{Sid}): 100 RPS

Update Content Approval Request (POST /v1/Approval/{Sid}): 20 RPS

What You Need to Do

Implement Exponential Backoff: Ensure your application can handle HTTP 429 status codes by incorporating backoffs and retries.

Audit High-Volume Pipelines: If your service executes bulk script operations (such as creating or deleting content templates in high-concurrency bursts), adjust your client throttling to remain within these thresholds.

Twilio Heightened Awareness Period (HAP) – November 19, 2026 - January 4, 2027

Between Thursday, November 19, 2026 and Monday, January 4 2027, Twilio will enter a Heightened Awareness Period (HAP) to help ensure reliable message delivery during peak traffic times, such as Black Friday and Cyber Monday.
During this period, message sending rates to U.S. destinations will be monitored and may be limited at the account level for toll-free, short code, and 10DLC numbers.
Accounts that send high volumes of messages from short codes or toll-free numbers may be temporarily migrated to Market Throughput during the HAP. Customers will be notified via email if their account is affected. Market Throughput doesn’t affect 10DLC numbers, which will continue to live on Account Based Throughput .
For more information on how throughput limits may be impacted and what actions to take, customers can reach out to their Twilio account team.

Webhook Configuration API is now in Public Beta

Using the Webhook Configuration API, customers can configure how Twilio authenticates and delivers outbound webhooks, per URL. The API consists of two resources: Webhook Settings and Webhook Rules.
Webhook Settings hold the authentication and connection configuration. Customers can secure endpoints with OAuth 2.0. Twilio fetches an access token from the customer's authorization server using the client credentials flow and sends it as a Bearer token in the Authorization header of every webhook or with Shared Key signatures. Customers can also configure delivery behavior like timeouts and retries.

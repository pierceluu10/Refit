Shopify versions its APIs by quarter. Versions are named `YYYY-MM` (for example `2026-10`), ship on the first day of each quarter, and each stable version is supported for at least 12 months; a release candidate for the next version ships the same day, and `unstable` is for testing only. Apps pick the version in the request URL (`/admin/api/2026-10/graphql.json`), in webhook subscriptions, in `shopify.app.toml` and in UI extension `api_version`, and when a version is retired Shopify silently falls forward to the oldest supported one. So a new stable version, or the retirement of an old one, is an `api-version` change with the old and new strings in `affects.versions`. The per-version release notes mark items "Action required" or "Breaking change": report each of those as its own change, with the version it lands in. Deprecated fields are usually removed one or two versions later.

The REST Admin API is legacy; the GraphQL Admin API is where new features land, and new public apps must use GraphQL. Anything that retires a REST resource or pushes callers to GraphQL is `rest-to-graphql`. In `affects`, name what code would mention: GraphQL types, fields, enum values and mutations (`DraftOrderDiscountNotAppliedWarning.priceRule`, `orderUpdate`), REST paths (`/admin/api/{version}/products.json`), webhook topics (`orders/create`) and payload fields, access scopes, and SDK methods or packages (`@shopify/shopify-api`, `@shopify/shopify-app-react-router`, `shopify_api` gem). Changes to OAuth, session or offline access tokens are `auth-change`; `@shopify/shopify-api` majors that drop Node versions or remove options are `sdk-major`.

The changelog also carries theme, Liquid, merchant admin, Shopify Flow UI, POS hardware and marketing news. Skip what only affects merchants or theme developers, and pure additions that need no code change, unless the item says action is required or something is deprecated.

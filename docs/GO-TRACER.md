# Go tracer

Refit reads Go code for calls to stripe-go (v71 and later), openai-go and anthropic-sdk-go, reports the Stripe API version each required stripe-go release pins, and reports every OpenAI and Anthropic model a call can send against `data/deadlines.json`. It is detection and reporting only: Go is never edited. Decisions: [Language goals](LANGUAGE-GOALS.md#go-decisions-2026-10-22). Written 2026-10-22 for lane FG2.

## Where it shows up

- `traceGoCalls(directory)` in `pipeline/go/calls.ts`: every traced call as an `SdkCallRecord` (`language: 'go'`), plus `modules`: each `go.mod` requirement of the three SDKs with its version, whether `go.sum` lists it, and for stripe-go the API version that release pins (`data/go-sdks.json`, generated by `scripts/go-sdks.mjs` from each release's `api_version.go` or `stripe.go`; v71.0.0 pins `2020-03-02`, v87.0.0 pins `2026-09-30.endive`).
- `scanDeadlines` (so `refit deadlines` and the hosted inventory) matches registry models in `.go` files, as string literals or as openai-go and anthropic-sdk-go model constants (`openai.ChatModelGPT4` → `gpt-4`), with the matcher's use classes: comments, comparisons and `strings.HasPrefix`-style checks, map keys and lists of three or more models, and `_test.go` files and files under test, example and end-to-end or system test directories (`e2e_test/`, `integration_tests/`, [as in TypeScript](DEADLINES.md#live-and-non-live-evidence)) are not live.
- `refit deadlines --propose-model-fixes` and `proposeModelReplacements`: every traced Go request that sends a retiring model is a stop with the TypeScript rule's reasons; other live Go matches are listed as not sent by a traced request. No replacement or patch includes Go.

## What is traced

- Clients: `stripe.NewClient(...)` (`sc.V1PaymentIntents.Create`), `client.New(...)` from stripe-go's `client` package (`sc.PaymentIntents.New`), stripe-go resource packages (`paymentintent.New`, `checkout/session.Get`; not `webhook`, `form` or `client`), `openai.NewClient(...)` and `anthropic.NewClient(...)`, through local and package-level variables, parameters, `var` declarations and struct fields typed `*openai.Client`, `anthropic.Client`, `*client.API` or `stripe.Client`, in any file of the same package.
- Models: the `Model` field of a params struct literal, passed directly or through a variable (including a later `params.Model = …`), followed through string literals, SDK model constants (the union of every release's constants), conversions and wrappers (`openai.ChatModel(…)`, `shared.ChatModel(…)`, `anthropic.Model(…)`, `openai.F(…)`), constants and variables in the function or package, every value assigned to a variable, struct fields through their own struct type (its literals and its methods' assignments), the return values of functions and methods in the same package, map lookups on map literals, and `cmp.Or`. Stops: `os.Getenv` without a fallback in the same expression, fields whose struct type Refit cannot tell, function parameters (callers are not followed in Go), calls into other packages, unknown SDK constants, params that are not a struct literal.

## Benchmark

Set: `docs/benchmarks/2026-10-22-go-repos.json`, 32 repositories from GitHub code search for the three module paths (`node scripts/python-models-select.mjs --go`), pinned commits. Labels: `2026-10-22-go-labels.json`, 16 repositories in seeded order (three over 130 candidate lines skipped), committed before the tracer ran on them: 84 SDK calls (29 Stripe, 35 OpenAI, 20 Anthropic) and 25 model sites after the adjudications below. Held-out: `2026-10-22-go-heldout-labels.json`, 3 more repositories labelled with the tracer frozen. Scorer: `npx tsx pipeline/go/benchmark.ts --root <checkouts> --output <results.json> [--labels …]`, tested in `pipeline/go/benchmark.test.ts`; results at 25c1613 in `2026-10-22-go-results.json`.

A reported line is a traced Stripe call or a model site an OpenAI or Anthropic call can send. Line precision counts both.

By provider at 25c1613 (labels): OpenAI calls 35/35, sites 5/8 found, 5/5 reported correct; **Anthropic** (the "Keep going" SDK) calls 20/20, sites 13/17 found, 13/13 reported correct.

Read these honestly:

- The first run's only "wrong" site was a labelling miss; four adjudications (in the labels file) add SDK-constant fallbacks the labeller missed in one repository. Three of the four were found by reading, not by the tracer, and lower measured recall.
- The fixes after the first run (nested Stripe resource packages such as `checkout/session`, struct fields through their own struct type, package function results, map lookups) were made with the labelled repositories in view. The held-out set is the only measurement with the tracer frozen; it is small.
- Provenance: the first run's row has no committed output, so it rests on the session's notes. `2026-10-22-go-results.json` records no Refit commit (the benchmark records `refitCommit` and `dirty` from now on), so 25c1613 is not tied to the file. Its `checkedAt` (10:50:31Z) already includes the held-out repositories, 29 seconds before the held-out labels were committed (4045ea5, 10:51:00Z), so the history cannot show those labels were written before the tracer ran on them.
- Remaining misses: models passed as function parameters across packages (callers are not followed in Go), defaults read through the application's own option getters, configuration defaults in other packages, and audio model constants outside `shared/shared.go`.

On the whole set (32 repositories, 25c1613): 216 traced calls in 29 repositories, 87 of them Stripe; 14 stripe-go requirements in `go.mod`, all with a known pinned API version.

## Not covered

Code generation templates, `vendor/` and `testdata/`, `_test.go` files, other Go SDKs (go-openai by sashabaranov, langchaingo, Bedrock through the AWS SDK), raw HTTP requests and `go.work` workspaces. A file past 2 MiB is a named stop (`file-too-large`), and past 10,000 files or 50 MiB per repository the whole language is one (`scan-limits`). Parse-time, node-count and depth limits stop a file the same way; see [Rules every tracer must satisfy](ARCHITECTURE.md#rules-every-tracer-must-satisfy).

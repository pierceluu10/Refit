Details: the #328 and #329 bodies and #269's body.
- **Declared API version conflicts (8):** two clients pinned to different versions, or a webhook-only client on another pin. This is an applicability safety stop (L1's gate), not a rule gap.
- **Broken source (4):** files that do not parse in the repository itself.
- **Helper taint (2), documented stops (2):** an exported helper that taints a shared client; customer-wide `retrieveUpcoming` and `subscriptions.update` `coupon`.
- **Unresolved reads in drafts:** a long tail of single-repository shapes (non-Prisma database rows, Stripe list responses, `JSON.parse` output, app helper results). No shape repeats across enough repositories to prove generically; these are the AI's work.
- **Regressions by design (2):** `Charge.dispute` and misspelled event names are real type errors the stripe-node upgrade surfaces.

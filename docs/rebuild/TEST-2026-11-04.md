## Causes

**Why Refit lost on time and cost:** it ran the whole pipeline on all 3 repos, opening 6, 4 and 4 tasks, and most of its time and money went on work outside the locked criteria. Harness alone was $2.03 to $2.14 a repo.

**Why Refit missed the required changes:**

1. **It looks at recent changelogs, and these breaks are older or sit in old-shaped code.** The Clario break comes from a 2025 Stripe release. I searched the raw watch caches: Clario's Stripe read has no mention of `current_period` or `invoice.subscription` (the word "basil" appears once), Spotify's has no mention of the Universal Analytics shutdown, and Code-Review-Agent's has no mention of the three retired default model names. Groq, the third of those, was not read as its own provider on that repo.
2. **It treats a pin as safe.** The Clario match step assumed a pinned version can't break. Here the code does not match its own pin, and that assumption hid the bug.
3. **Tasks follow changelog items, not the broken code.** Several agents saw the broken code and stayed inside their task. On Spotify the agent named the dead analytics and called it out of scope. On Code-Review-Agent the inventory recorded no model strings ("no model string was captured by the scan").
4. **Upgrades get done whether needed or not.** It chases new SDK majors, which is what the locked list counts as harm here.

**"Verified" did not mean fixed in this test.** Refit labelled 9 tasks verified across the 3 repos, and none fully fixed a required change. Its advisory reviewer returned `has-concerns` on all 10 tasks it reviewed. Its labels were not used as verdicts.

**Why Claude Code missed them:** the prompt doesn't name a provider, so it mostly looked for failures it could reproduce, and retired models and removed fields don't fail in tests without keys. It read "the API" as the app's own API on 2 of 3 Opus runs. On Spotify both models, and on Clario Sonnet, ended by asking a question. All its tool calls were Bash. I searched those commands for provider docs, deprecation or changelog URLs and found none in any of the 6 runs, so it never looked up a provider's changes. Its numbers are low partly because it stopped early.

**Where Refit did better, by these criteria:** the only credit on a required change, and the only side to fix Clario's Groq models (recommended, not scored). It did look for provider changes, which Claude Code mostly did not.

**Where Claude Code did better, by these criteria:** far cheaper and faster, with less change to review, and no major upgrades. Three of its 6 runs changed nothing (Opus on Spotify, Sonnet on Spotify and Clario), which breaches no harm rule but still scores INVALID.

## Limits

- **n=3, one run per side, no retries.** This says little about the general rate.
- **The criteria favour older breaks.** Picks came from a rule, and then I read the code to confirm a real break. That removed 4 of the first 6 candidates (3 pinned Stripe repos, 1 with a fake test). So it does not measure behaviour on repos with nothing to fix, where Refit's not-affected verdicts might matter. Rejections on reading were from code reading only, not runs, so I may have missed a break in a rejected repo.
- **Required changes were my own reading, locked before running.** They count only what I confirmed at the pinned commit. Other changes either side made get no credit even if real, such as Refit's Groq, Spotify search limit and Firebase work, and Claude Opus's schema and wiring fixes. I did not verify those as live breaks. This can understate both sides.
- **The prompt is deliberately vague.** That is the brief's choice. A prompt naming the provider or a date could change Claude Code's result a lot, as could a user answering the questions it asked. Round 3 used a long prompt and got different results.
- **Refit's model mix.** Refit's fix agent ran Sonnet 5.5, and its match step runs on Opus per the code at this SHA. The Sonnet row matches the fix agent's model only.
- **No live provider calls in grading, and no keys.** The locked tests use mocks and the provider docs as read today. Provider docs were read through a fetch tool, and some retirement dates apply only to certain tiers (Groq's exclude enterprise contracts).
- **Own checks are weak for some changes.** "No worse" is mostly exit codes. Refit's `functions/` Firebase upgrade is not built or tested by any own check, and Sentry is not exercised, so those could be broken without showing here.
- **Blinding was partial.** A fresh subagent graded labelled diffs without the key. I wrote the criteria and tests and saw Refit's task list before grading. I also verified the grader's facts afterwards, and I resolved only the `gpt-6-luna` question it left open. Diff size and style could hint at the author.
- **Timing:** one side at a time on a shared laptop, in order Refit then Claude Code. Claude Code containers had `--memory=6g --cpus=8`. Refit's containers used its own defaults. Other work on the machine was not controlled.

### Cap effect on Refit

The brief's $10 cap is far below Refit's usual run cap ($2,000 in Round 3). No run reached it in total ($4.46 at most), but Refit holds up to $5 for each task when it starts, and these tasks run at once. On Spotify, with 6 tasks, two stopped with a `budget` outcome: Sentry (needs-review) and the Cloud Functions search-limit task (failed with an empty diff, which is why the CLI exited 1). The second's transcript says "stopped mid-turn: $0.2589 spent of this query's $0.1563". The holds competing for a small cap are the likely cause; I did not test a larger cap. Neither task was about G1 or G2, so the verdict stands, but Refit's Spotify task results might differ with a larger cap. Per the rules, no retry was made.

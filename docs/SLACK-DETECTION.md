# Slack detection

Refit has no Slack agent (`adapter: null` in the catalog). This page covers review-only detection: which Slack Web API methods a repository calls, which of those Slack has deprecated or retired, and where the repository uses incoming webhooks or the Legacy RTM API. Nothing here changes code, and nothing contacts Slack. [SLACK.md](SLACK.md) is a different topic: the notices Refit itself posts to Slack.

## List the Slack calls

```sh
refit slack --repository /path/to/app
refit slack --repository /path/to/app --json
```

Refit reads JavaScript and TypeScript source and `package.json` files, without installing or running anything. It reports three kinds of method call:

- **`@slack/web-api` WebClient calls.** `client.chat.postMessage(…)` on a `new WebClient(…)` held in a variable, a class property (`this.web = new WebClient()` or a property initializer) or created inline, with `WebClient` imported by name, through a namespace (`slack.WebClient`) or required by destructuring. `WebClient` also counts from `@slack/bolt` and the retired `@slack/client`. `client.apiCall('chat.postMessage', …)` and `client.paginate(…)` read the method from their first argument, literal or held in a `const`. `client.filesUploadV2(…)` sends `files.getUploadURLExternal` and `files.completeUploadExternal`. A parameter typed `WebClient` counts as a client.
- **Bolt calls.** `app.client.<group>.<method>(…)` on a `new App(…)` from `@slack/bolt`, and the `client` a Bolt handler receives: in a file that imports `@slack/bolt`, a parameter destructured as `{ client }` or `{ client: web }`.
- **Raw HTTP.** A string, template or `+` concatenation that starts with `https://slack.com/api/` (or a workspace host such as `acme.slack.com/api/`), or with a `const` holding one. The method is the segment after `/api/`. The URL is followed to the call it is passed to (`fetch`, `axios.post`, a helper), as `refit paypal` does.

Each call lists:

| Field | Meaning |
| --- | --- |
| `kind` | `web-api`, `bolt` or `url`. |
| `file`, `line` | Where the call starts. A URL no call uses is reported at the URL. |
| `methods` | The Web API methods the call sends; `[]` when a runtime value chooses the method. |
| `client` | The call as written: `client.chat.postMessage`, `app.client.views.open`, `fetch`. |
| `deprecation` | Slack's deprecation of the method, with the reason and the changelog post Slack's SDKs link, or null. |
| `notes` | Facts for review: a method `@slack/web-api` 8 removed and Slack's named replacement, a method no longer in the newest release, a method no recorded release defines. |
| `unknown` | Each thing Refit could not read, and why. |
| `use` | `test` for test, spec, story, fixture and example files. |

The scan also lists two report-only surfaces, with no deadline:

- **Incoming webhooks** (`webhooks`): `new IncomingWebhook(url)` from `@slack/webhook` or `@slack/client`, and requests to `https://hooks.slack.com/services/…` (or `/workflows/…`, Workflow Builder's webhooks) through `fetch`, `axios` or a helper. A webhook URL written out in full in source is noted, because the URL is a credential.
- **The Legacy RTM API** (`rtm`): `new RTMClient(…)` from `@slack/rtm-api` or `@slack/client`, and Web API calls to `rtm.connect` and `rtm.start`. Slack's Node SDK guide says the RTM API "isn't available for modern granular-permissions apps, and you can no longer create new legacy apps" ([rtm-api.md](https://github.com/slackapi/node-slack-sdk/blob/8730b5e3a7cee08a0ccfa44b7f792814f939a9cf/docs/english/rtm-api.md)).

Retired methods with a published date are also deadline-registry entries (`kind: "method"`, provider `slack`), so `refit deadlines` and the hosted inventory list each call site with its date. See [below](#registry-entries).

### What is read, and what stays unknown

- **Untraced clients.** A client passed between files or functions without a `WebClient` type, a client built by a wrapper library, and a `WebClient` subclass are not followed. A `{ client }` parameter counts only in a file that imports `@slack/bolt`.
- **Runtime method names.** `client.apiCall(name)` and `` fetch(`https://slack.com/api/${method}`) `` are reported with an unknown method.
- **Environment URLs.** A webhook or API URL read from `process.env` has no Slack host in source and is not reported.
- **Legacy webhooks.** Slack's SDK sources do not say how to tell a legacy custom-integration webhook from an app's webhook, and the two URLs look the same. Refit reports every incoming webhook and does not label any of them legacy.
- **What a deprecation means.** `deprecation` repeats what Slack's SDKs say. A method without one may still be deprecated in a changelog post Refit could not read (see [Blocked](#blocked-sources)).

## The recorded methods

[`data/slack-methods.json`](../data/slack-methods.json) is generated by [`scripts/slack-methods.mjs`](../scripts/slack-methods.mjs) from package sources read as text, never installed or run:

- **`@slack/web-api` 5.15.0, 6.13.0, 7.19.0 and 8.2.0** (the last release of each major; 8.2.0 is `latest` on npm): every `client.<group>.<method>` property in `dist/methods.js`, parsed with the TypeScript parser, the method it binds, the releases that define it and the newest release's `@deprecated` JSDoc. 329 properties. The build fails if a property's method changes between releases.
- **Slack's Python SDK deprecation warnings** (`slack_sdk/web/deprecation.py` in [slackapi/python-slack-sdk](https://github.com/slackapi/python-slack-sdk) at `ab4e498`, 2026-10-16): three lists of method prefixes, each warned about with one changelog post.
- **The `@slack/web-api` v8 migration guide's removed-method table** ([slackapi/node-slack-sdk](https://github.com/slackapi/node-slack-sdk) at `8730b5e`, 2026-10-19): five methods and Slack's replacement for each.

```sh
npm pack @slack/web-api@8.2.0 --ignore-scripts   # and 5.15.0, 6.13.0, 7.19.0
curl -o web-api-registry.json https://registry.npmjs.org/@slack%2fweb-api
git clone --depth 1 https://github.com/slackapi/python-slack-sdk
git clone --depth 1 https://github.com/slackapi/node-slack-sdk
node scripts/slack-methods.mjs --web-api 5.15.0/package --web-api … --registry web-api-registry.json \
  --python-sdk python-slack-sdk --node-sdk node-slack-sdk --checked-at 2026-10-22 \
  --output data/slack-methods.json
```

What the recorded sources say (checked 2026-10-22):

| Methods | Status in Slack's SDK sources | Changelog post Slack links |
| --- | --- | --- |
| `channels.*`, `groups.*`, `im.*`, `mpim.*`, `admin.conversations.whitelist.*` | Deprecated; "use the Conversations API instead". The first four groups are absent from `@slack/web-api` 7 and 8; `admin.conversations.whitelist.*` is in no recorded release. | `2020-01-deprecating-antecedents-to-the-conversations-api` |
| `stars.add`, `stars.list`, `stars.remove` | Deprecated: "Stars can still be added but they can no longer be viewed or interacted with by end-users". The SDK source says a sunset timeline will follow. | `2023-07-its-later-already-for-stars-and-reminders` |
| `workflows.stepCompleted`, `workflows.stepFailed`, `workflows.updateStep` | Steps from Apps "will no longer be executed starting September 12, 2024". Removed in `@slack/web-api` 8, no replacement. | `2023-08-workflow-steps-from-apps-step-back` |
| `files.upload` | "Planned sunset date … of 2025-11-12". Removed in `@slack/web-api` 8; replacement `filesUploadV2`. | `2024-04-a-better-way-to-upload-files-is-here-to-stay` |
| `rtm.start` | Removed in `@slack/web-api` 8, "deprecated since 2021"; replacement `rtm.connect`. | none |
| `oauth.access` | "A legacy method only used by classic Slack apps. Use `oauth.v2.access` for new Slack apps." | none |

## Registry entries

Two dated retirements are in [`data/deadlines.json`](../data/deadlines.json) as `kind: "method"` entries, whose versions are method names. `scanDeadlines` matches them against every live call site `refit slack` reports, so they reach `refit deadlines`, deadline alerts and the hosted inventory.

| Entry | Methods | Date | Source read |
| --- | --- | --- | --- |
| `slack-workflow-steps-from-apps` | `workflows.stepCompleted`, `workflows.stepFailed`, `workflows.updateStep` | 2024-09-12 | node-slack-sdk `docs/english/reference/web-api/interfaces/WorkflowStepView.md` at `8730b5e` |
| `slack-files-upload` | `files.upload` | 2025-11-12 | node-slack-sdk `docs/english/web-api.md` at `8730b5e` |

Both sources are the Markdown that Slack publishes on docs.slack.dev, read from Slack's own repository at a pinned commit. The other deprecations above have no date in any source Refit read, so they have no registry entry; `refit slack` still reports them.

## Measured on a frozen set

[`benchmarks/2026-10-22-slack-repos.json`](benchmarks/2026-10-22-slack-repos.json) was frozen before any scan by [`scripts/slack-select.mjs`](../scripts/slack-select.mjs). GitHub code search is unavailable to this environment, so candidates come from npm search, as for PayPal: 18 queries ("slack", "slack bot", "slack notification", "chatops", …), 4 pages of 250 each. A package qualified when its latest manifest declares `@slack/web-api`, `@slack/bolt`, `@slack/client`, `@slack/rtm-api` or `@slack/webhook` in `dependencies`, links a github.com repository and was published since 2022-01, excluding `@slack/` packages. The 60 with the most monthly downloads were frozen at `HEAD`; on the way, 4,802 candidates declared no Slack SDK, 1,635 were older, 19 linked no GitHub repository, 12 were `@slack/` packages, 4 repeated a repository and 3 repositories were unreachable. **The set is mostly libraries and agent frameworks with a Slack adapter, not end-user applications.**

[`scripts/slack-benchmark.mjs`](../scripts/slack-benchmark.mjs) fetches each repository at its pinned commit and runs `refit slack --json`, with no code installed or run and nothing sent to Slack. [`scripts/slack-score.mjs`](../scripts/slack-score.mjs) scores the results against hand labels.

### Labels

- **Development set, 20 repositories** ([labels](benchmarks/2026-10-22-slack-labels.json)): the first 20 of the frozen list that fit the scan limits and hold JavaScript or TypeScript. Labelled blind, from source, before `refit slack` ran on any of them: 248 Web API calls, 9 incoming webhooks, no RTM use. A label is one call that sends a Slack Web API method, at the line where the call starts, whatever the client's origin. A repository's own helper that wraps one request is labelled once, at the request inside it. The file records the full procedure.
- **Held-out set, 10 repositories** ([labels](benchmarks/2026-10-22-slack-heldout-labels.json)): the next 10 that fit. Labelled after the detection changes the development scores led to, and before those changes scanned them: 153 calls, 1 RTM use, no webhook.

Two label errors surfaced later and are left in the frozen files: `jogold/cloudstructs` `src/slack-app/provider.lambda.ts:120` is a real call (`apps.manifest.${operation}`) that the labels miss, and `coreplanelabs/switchboard` `src/channels/slack.ts:1634` and `:1653` are `files.uploadV2` calls the development grep could not see (it skipped method names with digits). Counting them would raise the development precision to 1.0 and lower its recall slightly.

Every matched call reported the labelled methods. The first scan followed only clients created with `new WebClient()` or `new App()` in the same file, Bolt handler clients and parameters typed `WebClient`. The development misses led to following typed class properties and constructor parameter properties, `web ?? new WebClient()`, local type aliases, `Methods` (the class `WebClient` extends), `const self = this`, and functions returning a client in the same file or imported, including through tsconfig `paths` aliases and `await import()` (`317c28b`, `046f4eb`, `279fb88`). The blind held-out score was measured after those. Its main miss was a private class method returning the client (`this.ensureAuth().chat.postMessage(…)` in `agent-messenger/agent-messenger`, 83 calls), so `2f9eea2` follows methods of the enclosing class too. That last held-out figure is therefore not blind.

What is still missed, in the development set at `2f9eea2`:

- **Clients typed with the repository's own interface** (55 in `coreplanelabs/switchboard`, 5 in `AgentWorkforce/relayflows`): a parameter typed `SlackDirectAudienceClient` or `SlackWebApiLike` that the caller fills with a WebClient.
- **Clients held by another object** (5 in `hubot-friends/hubot-slack`): `this.client.web.users.info(…)`, and a private field assigned from an untyped constructor argument.
- **Bolt apps returned by a function in a bundled path** (5 in `desplega-ai/agent-swarm`), one custom wrapper type in `getsentry/junior` and one `new URL(method, base)` request in `vercel/chat`.

Precision stays high because a call counts only when its receiver is traced to `@slack/web-api` or `@slack/bolt`; nothing is matched by method name alone.

### What the whole set calls

At `2f9eea2` ([results](benchmarks/2026-10-22-slack-results.json)), 53 of the 60 repositories scanned; 7 exceed the scan limits (`CopilotKit/CopilotKit`, `openclaw/openclaw`, `UsefulSoftwareCo/emulate`, `backstage/backstage`, `MemberJunction/MJ`, `hanzoai/bot`, `Natebreynolds/Clementine-AI-Assistant`). 40 make at least one live Web API call; 459 live calls were reported (370 WebClient, 63 Bolt, 26 raw HTTP), 13 of them with a runtime method name, plus 68 in tests and examples.

- **Deprecated or retired methods:** one live call, `oauth.access` in `howdyai/botkit`, the classic-app OAuth method. No repository in the set calls `files.upload`, the conversations antecedents, `stars.*` or the Steps from Apps methods, so no registry deadline matched. This sample is recent, maintained libraries; the detection is for older applications, and this set does not measure how common they are.
- **Methods no recorded release defines:** 8 calls, all through `apiCall`: `assistant.search.context`, `apps.developerInstall`, and six undocumented client methods in `agent-messenger/agent-messenger` (`client.counts`, `saved.list`, `drafts.list`, …).
- **Incoming webhooks:** 11 live findings in 7 repositories. **Legacy RTM API:** 1, `rtm.connect` in `agent-messenger/agent-messenger`.

## Blocked sources

The lane asked for the api.slack.com changelog and deprecation pages. From the environment that built this, `api.slack.com` and `docs.slack.dev` do not resolve (DNS failure through the network proxy, for both `curl` and a page fetcher), so those pages were not read and no fact here comes from them. The changelog URLs in the table are the links Slack's own SDK sources carry, not pages that were opened. What would unblock it: read those four posts from a machine with access, and add any dated retirement (for example of the conversations antecedents or `stars.*`) as a registry entry with that page as its source.

# Gut inventory

Written 2026-10-31 for the wave-2 agents of the gut plan (GUT1 to GUT5). It lists every stop, hand-written fix, structured AI call, judge and data file in the Shopify, Meta Graph and Stripe pipelines and the shared code, says what replaces each one, and splits the files between the agents so no two edit the same file.

## How to read it

- **Basis.** Line numbers are from `bench/iter1-shopify-meta` at `68b73d83` merged with `feat/shopify-sdk-path` (#434) at `b4dffdfc`, which is what `refit/gut` will be. The pipeline code merges cleanly (only `docs/BENCHMARKS.md`, `docs/READINESS.md` and `docs/benchmarks/fix-reviews.json` conflict). Files #434 does not touch have the same lines on `bench/iter1-shopify-meta`. #434 also brings main's AI-migration work, because it merged main.
- **Categories:**
  - **STOP:** a place a repo ends without a patch. Each one becomes a hand-off to `fixWithAgent` (GUT1), with the stop's reason and findings as `context`.
  - **FIX:** hand-written patch logic. Marked **delete** (the agent replaces it) or **codemod** (cheap and always right; it keeps running first as a head start).
  - **AI-SNIPPET:** a `requestStructuredOutput` caller. Marked **replace** (fix-or-decline; the agent replaces it) or **keep** (narrow extraction feeding a judge, or data extraction checked by a verifier).
  - **JUDGE:** schema validation, contract provers, sandbox checks, live proof, proof grades. All kept.
  - **DATA:** provider data. All kept.
  - **DEAD:** tests, docs, flags or config that only serve deleted items.
- **Finders** (tracing and pin detection) are kept and not counted. Their "cannot read" reasons are not stops themselves; the pipeline turns them into stops, and that is the line to change.
- Hand-off context means the old stop text, its findings (file, line, expression) and the provider data the stop quotes.

# Cloudflare

Refit has no Cloudflare agent (`adapter: null` in the catalog). This page records what Cloudflare publishes about its API and covers review-only detection: which Cloudflare API endpoints a repository requests, which of those Cloudflare has deprecated, and each Worker's compatibility settings. Nothing here changes code, and nothing contacts Cloudflare.

### How the `cloudflare` npm SDK maps to endpoints

From 3.0.0 (2024-04-02) on, the `cloudflare` package is generated by Stainless from Cloudflare's OpenAPI spec, as its source files state. Each resource is a class extending `APIResource`. Its methods make one request each through `this._client.get|post|put|patch|delete(path)` or `this._client.getAPIList(path, Page)`, with the path as a template, and its properties hold sub-resources: `client.zones.settings.edit()` sends `PATCH /zones/{zone_id}/settings/{settingID}`. The client also exposes `client.get('/path')` and the other verbs for any path. In 7.3.0 each class also has a `_key` array, and the methods move to a `Base…` class that the exported class extends; 6.5.0 has neither.

Releases 2.x and earlier are a different, hand-written client: `require('cloudflare')({ token })`, with `cf.zones.browse()` and `cf.dnsRecords.add()`. 2.9.1 is its last release (2021-08-30). Refit reports its calls but does not map them to endpoints.

[`data/cloudflare-endpoints.json`](../data/cloudflare-endpoints.json) is generated by [`scripts/cloudflare-endpoints.mjs`](../scripts/cloudflare-endpoints.mjs). The script parses unpacked tarballs of the last release of each major from 3.x to 7.x (3.5.0, 4.5.0, 5.2.0, 6.5.0 and 7.3.0) with the TypeScript parser and never installs or runs them. It walks the resource classes from the `Cloudflare` client class and records each property path's HTTP method, path and releases: 2,936 properties. 71 of them changed their request between releases (for example `apiGateway.operations.create`). The data keeps one entry per request with its releases.

```sh
npm pack cloudflare@7.3.0 --ignore-scripts   # and 3.5.0, 4.5.0, 5.2.0, 6.5.0
curl -o cloudflare-registry.json https://registry.npmjs.org/cloudflare
git clone --depth 1 https://github.com/cloudflare/api-schemas
git clone --depth 1 --sparse https://github.com/cloudflare/cloudflare-docs
git -C cloudflare-docs sparse-checkout add /src/content/release-notes/ /src/content/compatibility-flags/ \
  '/src/content/docs/workers/configuration/compatibility-flags*'
node scripts/cloudflare-endpoints.mjs --sdk 3.5.0/package --sdk … --registry cloudflare-registry.json \
  --schemas api-schemas --docs cloudflare-docs --checked-at 2026-10-22 --output data/cloudflare-endpoints.json
```

### API deprecation announcements

Cloudflare's [API deprecations page](https://developers.cloudflare.com/fundamentals/api/reference/deprecations/) is rendered from `src/content/release-notes/api-deprecations.yaml` in [cloudflare/cloudflare-docs](https://github.com/cloudflare/cloudflare-docs). It was read at `ea89e14` (2026-10-22). The developers.cloudflare.com site itself does not resolve from the environment that built this (see [Blocked](#blocked-sources)), so the facts come from that file.

- **49 entries.** Each has a title, a publish date, and usually "Deprecation date" and "End of life date" lines. 16 give an exact end-of-life day; one gives only a month (Mirage, "January 2026").
- **Endpoints are listed under headings.** "Deprecated APIs" lists endpoints that go away, and "Affected APIs" lists endpoints that stay and change behaviour. Refit records which heading each endpoint was under: 127 deprecated and 44 affected, from 29 entries.
- **Request shapes count as affected, not removed.** Under "Deprecated APIs", Gateway Audit SSH lists `POST /accounts/{account_id}/gateway/rules` "— creating rules with `action: "audit_ssh"` is no longer accepted". That retires one request shape, not the endpoint, so a listed endpoint followed by "with `…`" is recorded as affected.
- **Some entries list no endpoint.** These describe field or behaviour changes in prose: Foundation DNS, Service Key Authentication and DNS record type updates.

## List the Cloudflare requests

```sh
refit cloudflare --repository /path/to/app
refit cloudflare --repository /path/to/app --json
```

Refit reads JavaScript and TypeScript source and `package.json` files, plus `wrangler.toml`, `wrangler.json` and `wrangler.jsonc`, without installing or running anything. It reports:

- **SDK calls.** `client.zones.settings.edit(…)` on a `new Cloudflare(…)` held in a variable or class property, created inline, returned by a local function, or a parameter or property typed `Cloudflare`. `Cloudflare` can be imported by default, by name or through a namespace, or required. Each property path maps to its recorded request. `client.get('/zones/…')` and the other verbs are read like a URL.
- **2.x factory clients.** `require('cloudflare')({ … })` and the same through an imported name, reported without an endpoint.
- **Raw HTTP.** A string, template or `+` concatenation that starts with `https://api.cloudflare.com/client/v4`, or with a `const` holding it, followed to `fetch`, `axios` or a helper, as `refit paypal` does.

Each request lists `kind` (`sdk` or `url`), `file` and `line`, `property` (the SDK path), `client` (the call as written), and `method` and `path`, with runtime path segments in braces. It also lists:

- **`notices`.** Every deprecations-page entry that lists the endpoint (`deprecated` or `affected`, with its dates), or the OpenAPI document's deprecation when the page has none.
- **`notes`.** A property no recorded release defines, or one missing from the newest release.
- **`unknown`.** What could not be read.

### Workers compatibility settings

Each Wrangler configuration file's `compatibility_date` and `compatibility_flags` is listed, at the top level and per `env.<name>` block, as an inventory fact. Cloudflare's [compatibility dates](https://developers.cloudflare.com/workers/configuration/compatibility-dates/) page says "The Workers runtime will support old compatibility dates forever", and that an upload without a date gets the oldest one (2021-11-02). So none of these facts is a deadline or an alert. Refit adds:

- the date's age in days, with a note when it is more than a year old;
- the flags Cloudflare's compatibility flags list turns on by default for later dates, which the Worker neither sets nor disables (`laterDefaults`);
- a note for a flag that is neither in the compatibility flags collection (128 flags, `src/content/compatibility-flags` at `ea89e14`) nor named in the page's Node.js section (`nodejs_compat`, `nodejs_compat_v2` and their `no_` forms).

### What stays unknown

- **Untraced clients.** A client passed between files or functions without a `Cloudflare` type, and requests through other libraries (Terraform, `wrangler` commands, `cf-api`-style wrappers), are not followed.
- **Runtime paths.** `` fetch(`${BASE}${path}`) `` and an axios instance created with a Cloudflare `baseURL` are not resolved. The first is reported with an unknown path; the second is not reported.
- **What a notice means.** A notice repeats what Cloudflare published about the endpoint. Many affected endpoints change only for one field or value, which Refit does not check in the request.

## Registry entries

Fifteen `kind: "endpoint"` entries in [`data/deadlines.json`](../data/deadlines.json) carry the dated endpoint retirements. Their versions read `GET /zones/{zone_id}/settings`; matching treats every `{…}` segment as equal. `scanDeadlines` matches them against the live requests `refit cloudflare` reports, so they reach `refit deadlines`, deadline alerts and the hosted inventory.

- **Ten come from the deprecations page.** Each is an entry with an exact end-of-life day and endpoints under "Deprecated APIs". The source is the page's YAML at `ea89e14`.
- **Five come from the OpenAPI document.** These are `x-cfDeprecation` notices with an `eol` date for endpoints the page entries above do not cover. The source is `openapi.json` at `d3e86ee`.

Entries without an exact date get no registry entry, though `refit cloudflare` still reports their endpoints. These include Firewall Rules, the previous WAF managed rules and Rate Limiting APIs, Organizations and Mirage.

## Blocked sources

`developers.cloudflare.com` does not resolve from this environment (DNS failure through the network proxy, for `curl` and a page fetcher). The facts above come from the Markdown and YAML Cloudflare's docs site is built from, in Cloudflare's own repository at a pinned commit, not from the rendered pages.

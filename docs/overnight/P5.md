## How each merge is checked

For every PR with a current `READY <commit>` comment, in order of size (smallest first):

1. The `READY` commit is the PR head and merges cleanly with `origin/main`.
2. On the merge result, in a dedicated worktree: `npm run typecheck`, `npm run format:check`, `npm test -- --maxWorkers=2`, `npm run build`, plus the gated suites the PR touches (oasdiff always; PostgreSQL for hosted code; Docker for validation and preparation code, under the shared Docker lock; real SDKs when the PR touches SDK upgrades).
3. Behaviour changes carry before and after GitHub Actions runs on the same subset, and every new or changed fix diff is labelled in `docs/benchmarks/fix-reviews.json`.
4. A default change meets the decision bar and adds its `AGENTS.md` bullet.
5. Nothing breaks the shared rules (secrets, untrusted code, file ownership).

Merges use `git merge --no-ff origin/<branch> -m "feat: merge #<n> <title>"` from a clean checkout of `origin/main`.

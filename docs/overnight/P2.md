  - On the 17 recorded agent diffs, main's guard refuses 5 of the 16 wrong patches, and 2 of the 7 wrong ones that passed validation.

  - The one correct diff passes both guards. Refit's own correct AI fix (VANTAGE, October 22), rebuilt from its recorded description because the diff was not kept, passes every new check in a test.
- **Spend: at most $0.09, all on Actions.** Local spend is $0, because the P2 key is not an API key (Blocked).
- **Design answers:**

## Why so few repositories reach the AI

`refit run` asks the model only when all of these hold (`useAi` in `pipeline/run.ts`, `validateMigration` in `pipeline/validation.ts`):

- the scan has confirmed findings, and the checks ran with a passing baseline;
- a rule's edit leaves some confirmed finding uncovered, or an operation is affected;
- no configured migration (a reviewed operation, request or webhook rule) owns the change.

Repair runs only after the patched checks fail. Before the request, it stops if the failure is one an owner policy reserves.

## Design questions

**Should an AI patch publish as a normal draft or always `[Needs review]`?** Always `[Needs review]`.

- 7 of the 8 recorded agent patches that passed validation were wrong, and passing checks told the reviewer nothing about any of them. Each dropped the card restriction, and no check sends a request to Stripe.
- Of Refit's own 3 passes on October 22, 1 was partial: the model chose the subscription item.
- The guard now refuses every class on record. A class nobody has seen yet would still validate, and publish as a normal draft.
- Today an AI patch with no unresolved findings publishes without the prefix (`needsReview = Boolean(waiver || patch.unresolvedFindings)` in `pipeline/review.ts`). That file is P4's, so I sent the change to P4 rather than making it here.

**Is repair worth its cost (fixes per dollar)?** No, not today.

- On October 22, 9 repair requests cost $0.058 and produced 0 correct fixes (1 partial, 1 regression).
- On main, 0 of the 9 regressions reach the model. Each is a stop that an owner policy reserves (`trial_from_plan`, item choice, `payment_method_types`), so a model repair of any of them would be wrong by policy.
- Keep repair off by default in the CLI. The benchmark's single attempt costs nothing, because it never starts.
- Revisit when an owner decision gives `trial_from_plan` a replacement.

**Is gpt-5.6-luna right? Try one stronger model on the 10 hardest cases.** Keep luna. The stronger-model run is Blocked.

- The only stronger-model evidence is the October 21 agent comparison: Codex CLI with `gpt-5.6-sol` was wrong in 7 of 8 validated patches, and in 16 of 17 overall.
- Its errors are policy errors (dropping a parameter the owner forbids dropping, choosing an item), not capability errors, so a stronger model makes the same choices.
- luna's correct VANTAGE fix cost $0.0049.
- I could not run the 10 hardest cases on a second model. The local key returns HTTP 401, and the Actions workflow pins `OPENAI_MODEL=gpt-5.6-luna`.

**Where does AI beat a rule we could write instead?** Nowhere measured. Every AI request on main is either VANTAGE's or refused by the evidence limit.

- VANTAGE's correct fix routes `(subscription as any).current_period_end` through the generated `getSubscriptionPeriodEnd()` helper. That is the existing period rule applied through an `as any` cast, which a rule can do deterministically (sent to F4).
- `trial_from_plan` (6 regressions) needs an owner decision before any rule or model may replace it.

## Known gaps

- **Untraced cached factory (F1).** A client built by a cached factory (`let cached: Stripe | null` in `sammorrispb/nextgen-academy`) is untraced, so no request or read check applies there.
- **Request bodies from other modules.** `droppedRequestPaths` follows `const` bodies and bodies returned by a function in the same file, not bodies built in another module.
- **Unrelated changes inside a covering edit.** An unrelated change inside an edit that covers its cited finding is not detected.
- **What the eval harness can express.** It checks one response shape, so neither version semantics (dual-shape reads) nor dropped request parameters can be eval cases; the replay and the policy tests cover both. Item choice has the `list-replacement` scenario. Invented fields and unrelated edits were already covered.

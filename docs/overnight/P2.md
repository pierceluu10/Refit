## Why so few repositories reach the AI

`refit run` asks the model only when all of these hold (`useAi` in `pipeline/run.ts`, `validateMigration` in `pipeline/validation.ts`):

- the scan has confirmed findings, and the checks ran with a passing baseline;
- a rule's edit leaves some confirmed finding uncovered;
- no operation is affected: an affected operation sets the AI path but then blocks generation (`pipeline/run.ts`, around line 416);
- no configured migration (a reviewed operation, request or webhook rule) owns the change.

Repair runs only after the patched checks fail. Before the request, it stops if the failure is one an owner policy reserves.

## Design questions

**Should an AI patch publish as a normal draft or always `[Needs review]`?** Always `[Needs review]`.

- 7 of the 8 recorded agent patches that passed validation were wrong, and passing checks told the reviewer nothing about any of them. Each dropped the card restriction, and no check sends a request to Stripe.
- Of Refit's own 3 passes on October 22, 1 was partial: the model chose the subscription item.
- The guard now refuses every class on record. A class nobody has seen yet would still validate, and publish as a normal draft.
- Today an AI patch with no unresolved findings publishes without the prefix (`needsReview = Boolean(waiver || patch.unresolvedFindings)` in `pipeline/review.ts`). That file is P4's, so I sent the change to P4 rather than making it here.

**Is repair worth its cost (fixes per dollar)?** No, not today.

- On October 22, 9 repair requests produced 0 correct fixes (1 partial, 1 regression). They recorded $0.0090 in bundles, a floor; the run's whole ledger was $0.058.
- On main, 9 of the 10 regressions stop before the model, each on a stop that an owner policy reserves (`trial_from_plan`, item choice, `payment_method_types`). A model repair of any of them would be wrong by policy.
- The tenth (madcaptees) reaches the model for a type error the shipping-details rule makes. A rule fix removes it for free, and deterministically.
- Keep repair off by default in the CLI. The benchmark's single attempt costs at most one request per such regression.
- Revisit when an owner decision gives `trial_from_plan` a replacement: F3's #285 keeps it and waits on that decision.

**Is gpt-5.6-luna right? Try one stronger model on the 10 hardest cases.** Keep luna until the comparison runs; the question is open, not settled. The stronger-model run is Blocked.

- The only stronger-model evidence is the October 21 agent comparison: Codex CLI with `gpt-5.6-sol` was wrong in 7 of 8 validated patches, and in 16 of 17 overall.
- That was a whole-repository migration, not Refit's bounded AI path on the same cases. Its main error, dropping `payment_method_types` (14 of 16), is one luna's path never faces, because the card rule or the scan stop handles that parameter first. The only class both share on record is item choice (iggy-tech).
- Its errors are policy errors, which the guard now refuses whatever the model.
- luna's correct VANTAGE fix cost $0.0049.
- I could not run the 10 hardest cases on a second model. The local key returns HTTP 401, and the Actions workflow pins `OPENAI_MODEL=gpt-5.6-luna`.

**Where does AI beat a rule we could write instead?** Nowhere measured. The AI requests on main are VANTAGE's first request and madcaptees' repair of a rule's error; cyberpunk-grok-api's is refused by the evidence limit before sending.

- VANTAGE's correct fix routes `(subscription as any).current_period_end` through the generated `getSubscriptionPeriodEnd()` helper. That is the existing period rule applied through an `as any` cast. I sent it to F4; F5's #279 now does it deterministically, and reports that VANTAGE's patch has 0 unresolved findings and validates locally (board, 11:49Z).
- madcaptees' repair would patch a narrowing error the rule can avoid (F5).
- `trial_from_plan` (6 regressions) needs an owner decision before any rule or model may replace it.

## Known gaps

- **Untraced cached factory (F1).** A client built by a cached factory (`let cached: Stripe | null` in `sammorrispb/nextgen-academy`) is untraced, so no request or read check applies there. On main, that repository stops for review on 8 unrelated review-confidence `description` reads, so the AI is not asked there. Nothing catches the untraced `payment_method_types` call itself. If the call were traced, this PR's policy would refuse the agent's correct patch there (the card rename), because only the reviewed card rule may make that change.
- **Request bodies from other modules.** `droppedRequestPaths` follows bodies declared in scope (with keys assigned to them later), bodies returned by a function in the same file and spreads of either. It does not follow a body built in another module, passed in as a parameter, filled by `Object.assign` or through an alias of the body.
- **Changed non-literal values.** A variable replaced by another variable is not compared.
- **Type escapes per file.** Escapes are counted per file and construct, so swapping an existing `any` for a new one in the same file passes.
- **Items passed to the app's own functions.** An item the AI picks and passes to a function that reads the period is not detected; reads through a variable, destructuring, string key or `Reflect.get` are.
- **Over-stops on repairs.** A repair that moves a helper call into a separate edit from the reads it feeds stops for review, because that edit no longer reads the old shape itself. A `Reflect.get` of a removed field on a traced response, outside a webhook, must also stay dual.
- **Benchmark outcome (O5).** `stripe-benchmark-cli.ts` (around line 529) records an `AiPolicyStop` as `error`, not `rejected-by-guard`; sent to O5.
- **Unrelated changes inside a covering edit.** An unrelated change inside an edit that covers its cited finding is not detected.
- **What the eval harness can express.** It checks one response shape, so neither version semantics (dual-shape reads) nor dropped request parameters can be eval cases; the replay and the policy tests cover both. Item choice has the `list-replacement` scenario. Invented fields and unrelated edits were already covered.

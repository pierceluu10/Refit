## Design: is the major upgrade needed, and how to make it compile

Options evaluated for class A, on the real snippets:

1. **Keep the SDK, cast the pin** (`apiVersion: '2026-09-30.endive' as Stripe.LatestApiVersion` on stripe-node 12). Rejected. The code then reads endive responses through 2022-11-15 types: Refit's own moved reads (`subscription.items.data[0].current_period_end`) do not exist in stripe-node 12's types, so all six would still fail to compile, and a read Refit missed would compile against the old shape. That is the dishonest case the lane warns about. Every class-A repository has such a moved read, so the upgrade is needed for all of them.
2. **Upgrade and drop or replace the property** (`trial_period_days` from the price). Rejected: it changes what the code sends, which owner decisions forbid without a documented equivalence, and a price lookup is not one-to-one.
3. **Upgrade and suppress the error** (`// @ts-expect-error` or `as any`), which the [stripe-node v13 migration guide](https://github.com/stripe/stripe-node/wiki/Migration-guide-for-v13) itself recommends "if sending the parameter is still required". Rejected as too wide: tested against stripe@23.0.0 with TypeScript 5.9, a `@ts-expect-error` on the property also hides a misspelled neighbour (`metadat`) in the same object, because TypeScript reports only the first excess property of a literal.
4. **Upgrade and spread only that property** (`...{ trial_from_plan: true }`). Chosen. Runtime is byte-for-byte the same request (same keys, same order). TypeScript skips the excess-property check for spread members only, so every other property of `subscription_data` is still checked: the gated test shows `metadat` still fails, and the spread compiles on both stripe@12.18.0 and stripe@23.0.0.

What the docs do not settle, and so what the draft asks: Stripe's API reference does not document `trial_from_plan` on Checkout at 2022-11-15 or at endive, and the [2022-08-01 changelog](https://docs.stripe.com/changelog/2022-08-01/removes-subscription-data-create-checkout-session) removed only `subscription_data[coupon]`. Refit cannot confirm from Stripe's documentation that Checkout still applies the price's trial at endive. A JavaScript repository sending the same property already gets the pin move with no question, because nothing flags it; the TypeScript stop was an artefact of the SDK's types. The draft is therefore `[Needs review]` and says: create a test-mode Checkout Session and check the subscription still starts with its trial, or send `subscription_data.trial_period_days` instead ([Checkout free trials](https://docs.stripe.com/payments/checkout/free-trials), read 2026-10-24).

Classes B and C stay stops on purpose: in both the upgraded types are right about the application.

## `@types/node`

stripe-node 23 declares `@types/node >=20` as an optional peer, and `stripePackageUpgrade` refuses when the lockfile installs an older one (`sdkUpgrade.skipped`). In run `40074110257` no row recorded that refusal, but 108 rows never reached the patch stage on a passing runner. Neither run of the 117-repository subset (below) recorded one either. Decision: Refit does not raise `@types/node` in the same patch. No repository tonight needed it, and raising it would change type checking across the whole app; the refusal stays, with its reason in the draft.

## Design question: one patch or two drafts?

One patch, for TypeScript repositories. Each stripe-node release types `apiVersion` as only its own version. Checked tonight with TypeScript 5.9:

- stripe@23.0.0 rejects `apiVersion: '2022-11-15'` (`TS2322: Type '"2022-11-15"' is not assignable to type '"2026-09-30.endive"'`);
- stripe@12.18.0 rejects the endive pin, and has no `SubscriptionItem.current_period_end`.

So a "moves first" draft fails its type check on the old SDK, and an "upgrade first" draft fails on the old pin. Two drafts would each need a cast on the pin, which is the dishonest option above. A customer reviews one draft whose SDK upgrade is listed separately in its body. JavaScript repositories have no such coupling, and could take two drafts; Refit leaves their SDK alone today (`stripe-package-upgrade.test.ts`, "leaves JavaScript projects on their installed SDK").

## Slice 1: check selection, evidence grades, named failures

PR: https://github.com/pierceluu10/Refit/pull/288.

- `selectCheck` (`pipeline/check-selection.ts`) is the one check selection for enrollment (`proposeStripeConfiguration`, which the hosted worker uses) and the Stripe benchmark. It never selects a no-op.
- The first version preferred tsc over a real test suite when no test imported Stripe code. Laptop 1 rejected that part on board #300 ("keep the tests and add the type check"), so now:
  - a real test script always runs; when it is one Vitest or Jest command and some test files reach Stripe code, only those files run (no other test reaches a file the patch can change);
  - a type check runs after the tests, or alone without tests: `tsc -p .` when the root program holds every file importing stripe, otherwise a generated tsconfig over those files and their importers (Refit's mounted compiler when the repository installs none and has no tests; none for a client only `require()` loads, which TypeScript leaves untyped);
  - the type check runs after failing tests too, so tests broken before the patch leave it as the evidence.
- Every validation outcome records a letter grade beside the first version's `level`: A (behaviour tests, reserved for the harness workstream), B, C or D. A benchmark repository with no check keeps its patch as grade D.
- A failing or timed-out check is named with its side, command (or chain part), first failure and the counts it reported.

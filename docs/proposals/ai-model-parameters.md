# Proposal: AI model changes Refit cannot fix safely today

Status: proposal, 2026-10-29. Nothing here is built or decided. It lists each class of OpenAI, Anthropic and Gemini model change that Refit finds but leaves alone. For each one it gives why a wrong fix would be worse than a stop, and what Refit would need to handle it. The decisions it asks for are owner decisions. Until one is recorded in `AGENTS.md`, behaviour stays as it is.

## Decisions requested

1. **Apply sourced parameter changes by default (item 2).** `data/model-parameter-changes.json` quotes each change verbatim from a saved official page (`npm run model-parameter-changes:check`). Today only `refit deadlines --propose-model-fixes --parameter-changes <path>` uses it, because of the 2026-10-22 decision that "a renamed parameter stops and is never rewritten". The decision asked for: `refit serve --model-fixes` applies the table's `rename` and `remove` changes with the swap. The draft lists each change with its note, and stays `[Needs review]` until a request-level proof shows the replacement accepts the new request shape. The changes it would apply:
   - `max_tokens` → `max_completion_tokens` on Chat Completions for GPT-5.6 and GPT-6 replacements. OpenAI's reference says `max_tokens` "is now deprecated in favor of `max_completion_tokens`". The draft notes that the new limit also counts reasoning tokens.
   - `temperature`, `top_p`, `top_logprobs` and `logprobs` removed for `gpt-6-luna` and `gpt-6-sol`. The GPT-6 migration guide says to remove them when reasoning effort is not `none`. A request that sets `reasoning_effort` or `reasoning` still stops.
   - `temperature`, `top_p` and `top_k` removed for `claude-opus-4-8` and `claude-sonnet-5-5`. Anthropic's deprecations page says they return a 400 "when set to a non-default value on Claude 4.7 and later models" and recommends omitting them.
2. **Gemini model edits.** Gemini is report-only (`adapter: null`). The registry now has 32 sourced Gemini model entries, but editing `ai.models.generateContent({ model })` needs:
   - a reviewed adapter for `@google/genai` and `@google/generative-ai`;
   - a `GEMINI_API_KEY` secret in refit-bench for request proofs.
3. **Request-proof keys.** Add `ANTHROPIC_API_KEY` and `GEMINI_API_KEY` repository secrets to refit-dev/refit-bench, each with a hard spend cap. Until then every Anthropic and Gemini replacement ships `[Needs review]` with that reason.
4. **Merge refit-dev/refit-bench#10** so `model-proof.yml` can be dispatched. A dispatch workflow must be on the default branch.

## Changes that stay alert-only, and what would be needed

| Change                                                                                                       | Why it is not fixed                                                                                                                                                                                                                                       | What Refit would need                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Embedding model retires (e.g. Gemini `text-embedding-004` → `gemini-embedding-2`)                            | Stored vectors are only comparable with vectors from the same model. A swapped ID makes new queries search old vectors from another model, which silently breaks results. The dimension can change too.                                                   | A migration plan the customer runs: re-embed every stored item into a new index, dual-read during the backfill, then switch queries. Refit could generate the plan and a script skeleton per vector store (pgvector, Pinecone, Supabase) and detect the store from code. The data move stays the customer's, because Refit cannot see or touch their data. |
| Fine-tuned `ft:` model whose base retires                                                                    | "Inference on fine-tuned models will be disabled only when the underlying base model is deprecated." No model ID replaces a fine-tune. OpenAI also ends new fine-tuning jobs for existing customers on 2027-01-06.                                        | Detect where the training data and job config live, and open an issue with the exact deadline and the job to rerun on a supported base. If fine-tuning itself closes, prompt-based alternatives with an eval plan. Never a code edit.                                                                                                                      |
| Model set in `.env*`, JSON, YAML or TOML                                                                     | Each deployed environment sets its own value; the committed file may be an example.                                                                                                                                                                       | Read hosting configuration through an integration the customer installs. That breaks the "install Refit and approve PRs" rule, so the alternative is an issue listing every key and where code reads it, which Refit now does.                                                                                                                             |
| `functions` / `function_call` (Chat Completions)                                                             | "Deprecated in favor of `tools`." Moving changes the response too: calls come back in `message.tool_calls` with IDs, not `message.function_call`, and results go back as `tool` messages. The request edit alone breaks the code that reads the response. | Trace the response reads (as the Stripe response-read tracer does) and rewrite request, response read and follow-up message together, with a test that replays a recorded tool call. A big feature; it needs its own decision.                                                                                                                             |
| GPT-6 tool calling on Chat Completions                                                                       | The GPT-6 guide says GPT-6 Sol and Luna "support function calling in Chat Completions only with `reasoning_effort: \"none\"`", and some GPT-6 models need the Responses API for tools.                                                                    | A Chat Completions → Responses migration rule (request and response shapes differ throughout). Until then a Chat Completions request with `tools` or `tool_choice` moving to `gpt-6-*` stops (built with this proposal, on by default because it only adds stops).                                                                                         |
| Anthropic extended thinking (`thinking: { type: 'enabled', budget_tokens }`)                                 | Already a stop. The mode the retiring models used differs from newer models', and budgets change output length and cost.                                                                                                                                  | A sourced change entry once Anthropic's migration guide states the replacement shape, and a request proof with an Anthropic key.                                                                                                                                                                                                                           |
| A replacement that is one of several (`whisper-1` → `gpt-live-transcribe` or `gpt-transcribe`, image models) | The provider leaves the choice to the customer. A person picked one in the registry, which `--check-sources` flags.                                                                                                                                       | These are audio and image calls, which Refit never edits. If they ever become editable, the draft must say the provider offered several and Refit chose.                                                                                                                                                                                                   |
| `gpt-5.6-*` replacements and `temperature`                                                                   | No OpenAI page states whether GPT-5.6 accepts sampling parameters, so they stop.                                                                                                                                                                          | The request proof's `rejected` list (HTTP 400 per parameter) is measured evidence. A decision on whether measured evidence may stand in for a page statement.                                                                                                                                                                                              |
| Anthropic API version `2026-10-21` removes sampling parameters for every model                               | Refit's edits assume the SDK's default `anthropic-version` header.                                                                                                                                                                                        | Trace the version header the client sends (the Stripe API-version tracer is the model) before relying on per-model rules.                                                                                                                                                                                                                                  |

## Not in scope

Pricing changes, rate limits and usage-policy changes: alert at most. None are fixed or alerted here.
